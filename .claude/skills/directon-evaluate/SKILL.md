# DIRECT:ON 평가

[공개 평가 기준과 체크리스트](references/rubric.md)를 읽는다. 사용자가 평가할 실행 결과나 제출물을 찾고, 가능한 점수와 근거, 미평가 항목을 보고한다. 정식 채점기 결과가 제공되면 대응하는 공개 기준과 함께 사용한다.

## 점수 계산

[scripts/score.py](scripts/score.py)는 Python 표준 라이브러리로 로컬에서 실행한다. 아래 경로는 평가할 프로젝트 디렉터리와 스킬 디렉터리에 맞게 지정한다. 기존 실행을 채점하는 요청에는 저장된 결과를 사용한다. `summary.json`은 실행 경로를 찾는 데 활용하고, 점수 계산은 컷오프에서 반올림 오차가 없도록 원본 `results.jsonl`의 초 단위 값을 읽는다.

```text
python <skill-dir>/scripts/score.py --results <run>/results.jsonl --mode fixture --cases <cases.jsonl>
python <skill-dir>/scripts/score.py --results <run>/results.jsonl --mode practice --cases <cases.jsonl> --review <review.json>
python <skill-dir>/scripts/score.py --official-system-score 84 --review <review.json>
python <skill-dir>/scripts/score.py --review <review.json>
```

- `--cases`에는 실제로 재생할 예정이었던 문항 목록을 지정한다. 단일 문항 재생은 실행 폴더의 `cases.jsonl`, 한국어 전체 실험은 `bench/fixtures/cases.jsonl`을 쓴다. 생략한 경우 결과에 포함된 문항만 분모에 들어간다. 설정 간 비교는 같은 문항 집합과 채점 근거를 사용한다.
- `fixture`는 응답과 호출을 미리 정한 재생이다. 첫 소리와 함수 뒤 유성 프레임을 비교하고, 응대·함수 점수와 시스템 합계는 미평가로 둔다. 정규식과 함수 일치율은 별도의 회귀 지표로 제시할 수 있다.
- `practice`는 실제 응답을 생성한 연습 실행이다. 응대는 고객 의도와 매뉴얼을 근거로 1/0.7/0을 판정한다. 함수는 필요한 호출의 함수명·인자·시점과 불필요한 호출 여부를 기록한다. 1/0 순수 일치와 문항별 동일 가중 평균은 연습 계산에 쓰는 가정이다. 모의 조회 결과가 정상적인 미조회 응답인 경우에도 요청 자체는 옳을 수 있다.
- 함수가 호출된 문항은 마지막 함수 응답부터 실제 본답변이 시작될 때까지 검토한 시간을 쓴다. `after_tool_sound`는 공식의 본답변 시각을 보장하지 않으므로 `speed_with_proxy`로 표시한다. `speed_score`에는 실제 본답변의 확인 시각을 쓰며, 함수가 없는 문항과 공개 기준상 속도 0점 문항도 집계한다. `turn.end` 25초 준수 여부는 함께 보고한다.
- 완전한 응대·함수·속도 판단이 모인 연습 결과는 `practice_estimate`로 표시한다. `--official-system-score`에는 운영진 또는 현장 배포 채점기가 제공한 시스템 점수 /100을 입력한다. 스킬의 정성 평가 점수와 시상 합계는 리허설 점수로 표시한다. 실제 시험의 음성·정답을 요구하거나 저장하지 않는다.

## 고객 체감 대기와 재생 시간

파이프라인 지연을 평가하거나 실행 결과를 비교할 때 공식 속도 점수와 별도로 고객의 대기·재생 타임라인을 초 단위로 보고한다. 가능한 경우 고객 발화 종료, 안내·본답의 실제 재생 시작과 종료, 재생 중 버퍼링 구간을 같은 시간축에서 확인한다.

- **첫 대기**는 고객 발화 종료부터 첫 음성의 재생 시작까지다. **중간 대기**는 안내 또는 앞 응답의 재생 종료부터 다음 본답 또는 응답의 재생 시작까지의 무음 구간이다. 여러 구간이 있으면 각각과 합계를 제시한다. 재생 중 버퍼링으로 멈춘 시간이 측정되면 별도로 표시하고 순대기에 포함한다. 발화 안의 자연스러운 쉼이나 음성 재생 시간은 대기에 더하지 않는다.
- **순대기**는 첫 대기 + 중간 대기 합 + 측정된 재생 중 버퍼링 대기다. 고객 발화 종료부터 최종 답변 재생 완료까지의 전체 시간과 별도로 보고한다. 중간 안내가 없는 통화의 중간 대기는 ‘해당 없음’으로 표시한다.
- 실제 재생 기록이 없고 음성 도착 시각과 각 음성의 길이만 있으면, 즉시·순서 재생 및 추가 끊김 없음이라는 가정을 명시하고 추정한다. 이때 앞 음성의 추정 종료는 재생 시작 + 음성 길이, 다음 음성의 추정 시작은 앞 음성의 추정 종료와 다음 음성 도착 시각 중 늦은 값이다. 중간 대기는 두 시각의 차이이며 앞 음성이 끝나기 전 다음 음성이 도착해 버퍼링된다면 0이다. 첫 가청 프레임 시각과 전체 WAV 길이의 기준 차이·앞뒤 무음 때문에 근사치임을 밝힌다.
- `after_tool_sound`는 함수 응답 뒤 첫 유성 프레임까지의 시간이며 앞 안내의 재생 종료를 반영하지 않으므로 중간 대기로 그대로 사용하지 않는다. `turn.end`는 전송 종료 신호이며 고객의 재생 완료가 아니다. 실제 재생 시각·음성 길이·본답 시작을 확인하지 못하면 필요한 항목을 미측정으로 두고 0으로 채우지 않는다. 발화 중 응답이나 실패·미완료는 별도 표시한다.
- 문항별 결과에 측정값 또는 추정값, 사용한 시간·음성 길이의 출처, 가정과 누락을 남긴다. 통계는 조건과 문항 집합을 나누고 유효 표본 수·중앙값·범위를 표시하며, 재생 중 멈춤 등 미측정 구간이 있으면 순대기 합의 불완전성을 밝힌다. 이 지표는 고객 경험 분석용이며 공식 속도 점수에 임의로 반영하지 않는다.

## 검토 입력

검토 결과를 아래 형식의 UTF-8 JSON으로 전달한다. 판단 근거는 보고서에 문항 ID·음성 시점·문서 위치와 함께 남긴다. 확인하지 못한 항목은 생략한다. 명시적인 `after_tool_answer_s: null`은 응답을 끝까지 검토해 실제 답이 없다고 확정한 경우에만 쓴다.

```json
{
  "cases": {
    "KO03": {"response": 0.7, "function": 1, "after_tool_answer_s": 0.4}
  },
  "qualitative": {"UX1": 2, "TALK1": 1, "PLAN1": 2}
}
```

발표 자료만 있으면 실제 질의응답, 텍스트만 있으면 실제 대화 속도·중간 개입처럼 관찰할 수 없는 항목은 미평가로 둔다. 근거가 있는 항목은 체크리스트의 항목별 척도를 사용한다. 부문별 점수와 배점, 채점 문항 수, 0점·미평가 사유와 가장 큰 감점 근거를 제시한다.
