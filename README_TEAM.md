# DIRECT:ON 2026 — 우리 팀 상담원 서버

> **이 저장소는 꼭 Private(비공개)로 두세요.** `data/` 에는 대회에서 받은 상담 자료와 음성이 들어 있고, 대회 규정(`README.md`·`DATA.md`)상 밖으로 공개하면 안 됩니다. **API 키(`agent_server/.env`)도 올리지 마세요** (`.gitignore` 가 막아 두었습니다).
>
> 처음 받았다면: ① `python -m pip install -r requirements.txt` ② `agent_server/.env.example` 을 `.env` 로 복사해 키 넣기 ③ 아래 "실행 방법"대로 서버 두 개 켜기.

전화로 들어온 손님 목소리를 **알아듣고 → 생각하고 → 목소리로 답하는** AI 상담원 서버입니다. (대회 규정과 채점 기준은 `README.md`, `SPEC.md`, `SCORING.md`가 원본입니다)
지정 모델: 받아쓰기 **Soniox stt-rt-v6** · 생각 **gpt-5.4-mini** · 말하기 **Gemini 3.8 Flash TTS** (`gemini-3.8-flash-tts`. 운영진 공지로 2.5 에서 변경)

```
손님 음성 → 상담원 서버(9000) → Soniox(받아쓰기) → gpt-5.4-mini ⇄ 전산실(8100, 측정기 중계 경유) → Gemini(말하기) → 음성 응답
```

## 현재 상태
- 끝까지 동작합니다: 음성 → 함수 호출(조회·접수) → 음성 응답. 오류가 나도 `turn.end`는 항상 보냅니다.
- 연습 문항 4개를 동시에(최종 측정과 같은 방식) 돌린 결과: **함수 100 · 속도 81 · 응대 50 → 총점 69** (표본이 4개뿐이라 참고만. 응대는 채점 AI 판정이 문항마다 흔들립니다).
- 함수를 부르는 답은 먼저 "네, 확인해 보겠습니다" 같은 짧은 한마디를 내보내서 첫 소리를 약 2초로 줄였습니다. (조회 뒤 실제 답은 약 2초)
- 그 뒤에 더한 것: BAZE 게이트웨이 연결(전화번호 가림 대응 포함), 유형별 매크로, 마이크로 멀티턴 대화 시험과 자동 채점(`eval/live_chat.py`), 말 끊기(끼어들기) 대응, 말 고치는 중·번호 말하는 중에 더 기다리기.
- 아직 안 한 것: 연습 80문항 전체 재측정, 받아쓰기 숫자 오인식 보정, 리눅스 파이썬 3.11 컨테이너에서 실제 실행 확인, 운영진 확인 사항(실시간 받아쓰기 소켓 허용 여부, TTS 모델이 flash 인지 flash-lite 인지).


## 실행 방법

### 1. 설치 (한 번만)
```powershell
python -m pip install -r requirements.txt
```

### 2. 키 넣기
`agent_server/.env.example` 을 `agent_server/.env` 로 복사한 뒤, 메모장으로 열어 키를 적습니다. 대회 현장의 **BAZE 게이트웨이 키**는 `BAZE_API_KEY=키값` 한 줄이면 되고(받아쓰기·생각·말하기를 모두 이 키로 부름), 서비스를 직접 부르려면 `OPENAI_API_KEY`, `SONIOX_API_KEY`, `GEMINI_API_KEY` 세 줄을 적습니다. (따옴표 없이 `이름=키값` 형태. `BAZE_API_KEY` 가 있으면 그쪽이 우선)
```powershell
copy agent_server\.env.example agent_server\.env
```
> `.env` 는 **절대 깃에 올리지 마세요.** (`.gitignore` 로 막아 두었습니다)

### 3. 키가 되는지 점검 (크레딧 1센트 안팎)
```powershell
python agent_server/check_apis.py
```
받아쓰기 → LLM → 말하기 순서로 한 번씩 불러 봅니다. 모두 "성공"이면 준비 끝입니다.

### 4. 서버 켜기 (터미널 2개)
```powershell
python mock_tools/mock_server.py --port 8100
```
```powershell
$env:PYTHONUTF8="1"; python agent_server/server.py --port 9000
```
`[준비 완료]` 가 나오면 됩니다. (고정 문구 음성은 `phrases/` 에 저장돼 있어 바로 준비됩니다. 목소리·모델·문구를 바꾸면 처음 한 번만 몇 분 걸려요)

### 5. 측정하기 (터미널 1개 더)
연습 문항 4개를 동시에 (같은 4개가 항상 뽑힙니다):
```powershell
$env:PYTHONUTF8="1"; python eval/run_eval.py --server ws://127.0.0.1:9000 --cases data/practice_cases.jsonl --audio data/audio/practice --mock http://127.0.0.1:8100 --out runs/try1 --sample 4 --concurrency 4
```
함수·속도 점수 (키 필요 없음):
```powershell
python eval/score.py --run runs/try1 --cases data/practice_cases.jsonl --no-judge
```
응대 점수까지 (채점기는 환경변수의 `OPENAI_API_KEY` 를 읽어요):
```powershell
$env:OPENAI_API_KEY="키값"; python eval/score.py --run runs/try1 --cases data/practice_cases.jsonl
```
- `--out` 이름은 **매번 새로** 정하세요. (같은 이름이면 이미 한 문항은 건너뜁니다)
- 결과는 **상담원 터미널**에서 봅니다: `고객:`(받아쓴 글) · `상담원:`(대답) · 단계별 시간 · `[사용량]`(추정 비용). `runs/<이름>/scored.jsonl` 의 `reason` 에 채점 AI가 깎은 이유가 있어요. 틀린 문항만 모아 읽는 게 프롬프트를 고치는 가장 빠른 길입니다.
- 전산실만 따로 점검: `python mock_tools/check_lookup.py` / 번호 가리기 장치만 점검: `python agent_server/check_mask.py` (둘 다 API 를 부르지 않아요)
- 번호가 든 어려운 문항 8개만 측정: 위 `run_eval.py` 명령에서 `--cases data/phone_cases.jsonl` 로 바꾸고 `--sample 4` 는 빼세요. (채점기 `score.py` 의 `--cases` 도 같은 파일로) (`data/phone_cases.jsonl` 은 연습 문항 중 전화번호로 조회·접수하는 것만 뽑은 파일)

### 6. 실시간 음성으로 멀티턴 대화 시험 (마이크 + 스피커)
측정기는 "말 한 번"만 재서, 티키타카 대화는 이 도구로 직접 해 봅니다. 말 한 번마다 규격대로 연결을 새로 열고 지금까지의 대화를 `history` 로 보내요. 서버 2개(8100, 9000)를 켠 뒤(서버를 새 코드로 다시 켜야 합니다):
```powershell
python eval/live_chat.py --list-samples
```
```powershell
$env:PYTHONUTF8="1"; python eval/live_chat.py
```
- **Enter 는 처음에 한 번만** 누릅니다. 그 뒤로는 마이크가 계속 켜져 있어서, 말을 시작하면 자동으로 한 번의 말로 보내고(서버가 말 끝을 판단해 답함) 상담원 말이 끝나면 다시 듣습니다. **끝낼 때 Enter 를 다시** 누르세요. 말할 때마다 Enter 를 누르는 방식은 `--manual`. **이어폰·헤드셋 필수**예요(스피커 소리가 마이크로 들어가면 상담원 말을 손님 말로 착각합니다). 말이 안 잡히거나 잡음에 걸리면 `--vad-rms` 숫자를 조절하세요(기본 500).
- 번호는 `--list-samples` 에 나온 것(전산실에 기록이 있는 번호)으로 말해야 조회가 됩니다. 걸려 온 번호가 있는 손님이면 `--caller 01058003641` 을 붙이세요. 말할 대본은 `LIVE_SCRIPTS.md` 에 있어요(대본마다 `--now`·`--caller` 가 정해져 있음).
- 말마다 `첫 대기`(말 끝 → 첫 소리), `중간 무음`(상담원 말 사이 끊김), 부른 함수가 나옵니다.
- **끝나면 자동으로 채점**해요. 말 한 번을 문항 하나로 보고 대회 채점기(`score.py`)의 점수표·함수 판정·응대 판정을 그대로 써서, 말마다 속도·응대·함수와 전체 점수를 보여 줍니다(연습용 점수). 응대 채점은 개인 `OPENAI_API_KEY` 로 채점 AI를 부르고(게이트웨이 키로는 안 됨), 생략하려면 `--no-judge`, 채점 자체를 끄려면 `--no-score`.
  - **속도**는 바로 계산돼요(첫 소리, 함수를 불렀으면 '조회 뒤 답'과 평균). 손님 말 끝은 마이크 소리로 어림한 값입니다.
  - **함수**는 '정답 호출'을 알려 줘야 채점돼요. 말 번호별 정답을 JSON 으로 만들어 `--expect 정답.json` 으로 주세요: `{"1": {"tool_calls": []}, "2": {"tool_calls": [{"name": "get_order_info", "arguments": {"buyer_cellphone": "01012345678"}}]}}`. 정답을 안 준 말은 함수 점수에서 빠지고, **총점은 모든 말에 정답이 있을 때만** 나옵니다.
  - 기록은 `runs/live/<날짜_시각>/`(`cases.jsonl`, `results.jsonl`, `agent_audio/`)에 남고, 나중에 다시 채점(가장 최근 대화): `python eval/live_score.py --latest`. **`Ctrl+C` 로 끝내도 지금까지의 말은 채점**해요.
- 마이크 없이 시험: `python eval/live_chat.py --wav 첫번째.wav 두번째.wav --no-play`
- **끼어들기(상담원 말을 끊고 말하기)가 됩니다.** 상담원이 말하는 중에(재생 중에) 말을 시작하면, 시험기가 그 자리에서 상담원 말을 멈추고 그 말을 곧바로 새 말로 이어 갑니다.
  - 끊긴 말은 **실제로 재생된 만큼만** 상담원이 한 말로 기록하고 끝에 `…(손님이 말을 끊음)` 을 붙여 다음 응대에 넘겨요. 채점기가 듣는 음성도 그만큼만 남고, 채점표에 `[손님이 상담원 말을 끊음]` 으로 표시됩니다.
  - 서버는 연결이 끊기면 하던 LLM·음성 합성을 바로 멈춰서 크레딧을 아끼고, `prompt.md` 의 "손님이 말을 끊거나 갑자기 화제를 바꿀 때" 규칙으로 끊긴 말을 처음부터 되풀이하지 않고 손님의 새 말에 먼저 답합니다.
  - **헤드셋 필수**예요. 스피커로 들으면 상담원 소리를 끼어들기로 착각하니 그땐 `--no-barge-in`. 끼어들기로 보는 볼륨은 `--barge-rms`(기본 1000, 헤드셋 말소리는 보통 2000 이상 / 잡음은 수백)로 조절하세요.
  - 이어지는 대화(기본) 모드에서만 동작하고, `--wav`·`--manual` 에서는 안 돼요. 서버에서 한 연결 안에서 끊고 이어 가는 방식(같은 연결 재사용)은 아직 아니에요. 규격대로 말 한 번마다 연결을 새로 엽니다.
  - 손님 말 도중에 답하는 '끼어듦'(상담원이 손님 말을 끊음) 판정은 여전히 마이크 소리로 어림한 값입니다.

### 내 목소리로 시험하고 싶을 때 (선택)
`python -m pip install sounddevice` 후 `python eval/record.py` 로 녹음하면 `data/audio/ko/` 와 `data/ko_cases.jsonl` 이 만들어집니다. 이어서 측정할 땐 위 명령의 `--cases data/ko_cases.jsonl --audio data/audio/ko` 로 바꿔 쓰세요.

## 유형별 매크로 (먼저 하는 말 → 본 답 → 끝맺음)
받아쓰기가 끝나면 LLM 을 기다리지 않고 **키워드로 유형을 바로 정해**, 미리 만들어 둔 한 문장(예: "주문 내역 문의 주셨네요, 바로 확인해 볼게요.")을 먼저 내보냅니다. 그 말이 나가는 동안 LLM 답과 음성이 만들어지고, 끝나면 본 답이 이어지고, 알려 주는 답이면 끝맺음("더 궁금하신 점 있으시면…")이 붙습니다.
- 유형: 주문조회 · 반품현황 · 접수 · 상품 · 정책 (`server.py` 의 `CASES`). 주문조회·반품현황·접수는 **번호가 있을 때만**(걸려 온 번호·앞선 조회 결과·말한 숫자 7자리 이상) 씁니다.
- **안 쓰는 경우** (LLM 이 알아서 답함): 키워드가 두 유형 이상에 걸릴 때, 건강·상담원·오배송·불만 같은 말(`SKIP_RE`), 이미 같은 말을 한 통화, 음성이 아직 준비 안 된 문구. 잘못된 매크로는 안 하는 것보다 나빠서 확실할 때만 씁니다.
- 매크로가 나간 통화에서는 채움말("네, 확인해 보겠습니다")을 또 하지 않고, LLM 에게 "이미 이렇게 말했다"고 알려 줘서 본 답이 같은 말을 되풀이하지 않게 합니다.
- 끄기: `.env` 에 `MACRO=0`. 문구를 고치면 서버를 켤 때 새 음성이 만들어져 `phrases/` 에 저장됩니다 (**제출 전에 한 번 켜서 새로 만들어졌는지 확인**).
- 점검: `python agent_server/check_cases.py` (API 안 부름. `-v` 를 붙이면 연습 80개 중 매크로가 걸린 문항을 보여 줌).
- 측정(연습 문항 중 매크로가 걸린 18개, 켬 대 끔): 첫 소리 평균 약 1.0초 대 약 2.7초, 속도 점수 약 93 대 약 63, 함수 점수는 차이 없음. 연습 80개 중 18개(약 22%)만 걸려서 전체 점수 효과는 작습니다. **남은 약점:** 함수를 부르는 문항은 매크로(약 2.5초)가 끝난 뒤 본 답이 올 때까지 무음이 3~4초 남습니다 (`live_chat.py` 의 `중간 무음`). 본 답을 만드는 시간(LLM + 게이트웨이 TTS)이 줄어야 사라집니다.

## 설정값 (`.env` 에 적거나 터미널에서 지정)
| 이름 | 기본값 | 설명 |
|---|---|---|
| `LLM_EFFORT` | (비움) | LLM 생각 강도 `low`/`medium` (높을수록 정확하지만 느림) |
| `END_SILENCE_MS` | 800 | 이만큼 조용하면 말이 끝났다고 판단 (**줄이면 말 중간에 끼어들 위험**) |
| `LONG_SILENCE_MS` | 1800 | 말이 `~는데`, `~하고`처럼 이어질 모양이거나, 번호를 다 말하지 않고(숫자 1~9자리) 쉴 때 더 기다리는 시간 |
| `CORRECT_SILENCE_MS` | 2500 | "잘못 얘기했는데", "아니 그게…", "잠깐만요" 같은 말 고치기 시작 말 뒤에 더 기다리는 시간 |

| `TTS_MODEL` / `TTS_VOICE` / `TTS_STYLE` | gemini-3.8-flash-tts / Kore / (비움) | 모델 / 목소리 / 읽어 달라는 지시. **3.8 모델은 지시어를 소리 내어 읽어서 비워 둡니다** (2.5·flash-lite 로 바꿀 때만 `Say: `) |

## 알아 둘 것
- **BAZE 게이트웨이 모드** (`https://api.baze.co/v1/gateway`, 분당 120회 한도): LLM `gpt-5.4-mini`, 받아쓰기는 실시간 Soniox 웹소켓 `stt-rt-v6`(지금 방식 그대로 됨), 말하기는 `gemini-3.8-flash-tts`. 실시간 받아쓰기 소켓은 게이트웨이 안내에 `stt-rt-v5` 로 적혀 있고 `stt-rt-v6` 이름으로도 동작했지만, **운영진이 실시간 소켓 사용을 허용했는지는 아직 확인 전입니다.** 안 되면 `stt-async-*`(5~7초)뿐이라 속도 점수가 크게 떨어져요. `stt-async-*`(파일을 올려 받아쓰는 방식)는 한 문장에 약 5초가 걸려 쓸 수 없습니다.
- **게이트웨이는 LLM·TTS 입력의 전화번호를 `[PHONE]` 으로 가리거나 다른 번호로 바꿉니다** (직접 확인: 전화번호 조회 호출의 인수가 `[PHONE]` 이 됨, TTS 가 010-4957-6966 을 010-6217-3333 으로 읽음). 그래서 서버는 LLM 에 보내기 전에 번호를 `<전화1>`·`<주문1>` 자리표시로 바꾸고 함수 호출·답에서 되돌리며, TTS 에는 `공 일 공, 사 구 오 칠, 육 구 육 육` 처럼 한 자씩 띄운 한글 숫자로 보냅니다(붙여 쓴 한글 숫자는 TTS 가 자주 실패). `python agent_server/check_mask.py` 로 점검합니다.
- **받아쓰기의 숫자 오인식이 함수 점수의 가장 큰 걸림돌입니다.** 번호가 든 연습 문항 8개 중 5개가 번호를 한두 자리 틀리게 받아써서(예: 4402→4002) 함수 점수가 깎였습니다. 손님이 길게 말하며 중간에 쉬면 말이 끝났다고 보고 먼저 답하는 문제도 있습니다.
- **게이트웨이 TTS는 음성을 조각으로 안 나눠 주고 통째로 줍니다.** 짧은 문장도 약 2.3초, 길면 길이에 비례해 느려집니다(150자 약 7초). 그래서 미리 만들어 둔 고정 문구(`phrases/`)와 함수 호출 때의 채움말이 중요하고, 게이트웨이는 문장별로 동시에 합성해 첫 문장부터 말합니다. (3.8 모델로 잰 연습 4문항: 게이트웨이 속도 약 48 / 개인 키 직접 호출(스트리밍) 약 81. 2.5 로 바꾼 뒤 전체 재측정은 아직. 함수를 부르는 답의 첫 소리는 채움말 덕에 약 2.2~2.6초.)
- **(직접 호출할 때) Gemini TTS 분당 호출 한도가 위험입니다.** 개인 키는 Tier 1 이라 **분당 10회**이고, 넘으면 429 오류가 납니다. 최종 측정은 4문항을 동시에 계속 보내서 이 한도에 걸릴 수 있어요. (서버는 "8초 이하 뒤에 다시"라고 알려 주면 기다렸다 한 번 더 시도하고, 그래도 안 되면 사과 음성으로 `turn.end` 를 보냅니다.) **현장에서 쓰는 키의 한도를 꼭 확인하세요.**
- **TTS 모델 이름이 문서마다 다릅니다.** 대회 원본 `README.md`·`SPEC.md` 는 `gemini-3.8-flash-lite-tts`, 운영진 공지는 "Gemini 3.8 flash", BAZE 게이트웨이 모델 목록에는 `gemini-3.8-flash-tts` 만 있습니다(2026-11-21 확인). 그래서 코드 기본값은 `gemini-3.8-flash-tts` 입니다. 개인 키로 직접 부를 땐 `TTS_MODEL=gemini-3.8-flash-lite-tts` 도 됩니다(지시어 없이). 어느 쪽으로 측정하는지는 운영진 확인 전입니다.
- 응대 규칙은 `agent_server/prompt.md`, 자주 쓰는 고정 문구는 `server.py` 의 `PHRASES`/`FILLERS` 입니다. 문구를 바꾸면 `agent_server/phrases/` 의 오래된 파일은 지워도 됩니다 (자동으로 새로 만들어요).
- 말 끝 판단은 "조용한 시간 + 말이 이어질 모양인지"로 합니다(`Stt.wait_ms()`): 기본 0.8초, 말이 이어질 어미(`~는데`)나 **번호를 말하다 만 모양**이면 1.8초, **말 고치기 시작 말**이면 2.5초. 연습 음성 6개(번호로 끝나는 말 포함)로 재 보니 보통 말은 이전과 똑같이 0.78초 뒤 끝났다고 판단했고, 번호 중간에 1.5초 쉬는 소리를 끼워 넣으면 이전엔 "010"에서 끊고 답했지만 이제는 번호를 끝까지 기다립니다. 받아쓰기가 마지막 글자를 한 박자 늦게 내줘서(`010`이 `01`로 보임) 숫자는 1자리부터 센다는 점에 주의하세요. 그래도 연습 음성 80개 중 4개는 말 중간에 0.8초 넘게 쉬어서, 이런 문항은 끼어들기(속도 0점) 위험이 남아 있습니다.
- `history` 의 함수 호출·결과는 OpenAI 의 `tool_calls` 형식으로 바꿔서 LLM 에게 넘기고, 상담원 말에 섞인 링크·이모티콘은 지웁니다.
